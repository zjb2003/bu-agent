# 清小搭适配说明

适用场景：将 `boundlessus-bu-assistant` 接入清小搭进行内部原型、受控试点和上线前验收。

本文件把“清华公开资料已确认的能力”和“登录后必须核实的界面能力”分开。平台具体字段、权限和工具范围发生变化时，以清小搭当前界面和项目管理员说明为准。

## 已确认的适配依据

截至 2026-09-02，清华公开资料将清小搭描述为基于知识库的智能助手，并提到知识库与智能体共创平台、MCP 服务中台等底层能力；清小搭官网提供网页版和微信小程序入口。[清华大学官方介绍](https://www.tsinghua.edu.cn/info/1182/125496.htm) ｜ [清小搭官网](https://www.xiaoda.tsinghua.edu.cn/login)

这些信息支持以下适配策略：用一个专门智能体承载 BU 的运行规则，用经过筛选的资料作为知识库，把测试案例作为人工验收集。它们不等于已经确认清小搭对当前账号开放了全部工具或字段。

## 底座选择建议

截图显示清小搭当前提供 `AgentVerse 2.0` 和 `Coze 开源版` 两个创建底座。公开资料不足以确认 AgentVerse 2.0 的全部技术细节，因此下面的首选是基于“清小搭原生入口优先”的工程判断，不是对未公开能力的事实声明。

### 首轮推荐：AgentVerse 2.0

如果两个选项都能创建普通知识库智能体，首轮建议先选 `AgentVerse 2.0`：

- 更可能与清小搭的账号、知识库、智能体广场和权限体系直接衔接；
- 先验证 BU 的核心问答、安全和知识边界，不引入自托管、模型配置和插件鉴权等额外变量；
- 更适合当前目标：先完成一个可控的内部原型，而不是立即搭建复杂的外部服务。

### 何时选择：Coze 开源版

只有在以下需求明确存在，并且你能承担部署与安全维护时，才优先考虑 `Coze 开源版`：

- 需要自己控制模型服务、数据库、工作流、插件或 API；
- 需要把多步骤审批、资源入库、结构化输出等逻辑做成可视化工作流；
- 需要二次开发、私有部署或从清小搭迁移到自有系统。

Coze Studio 的公开仓库明确支持 Prompt、RAG、插件、工作流、数据库、API/SDK 等资源，但自托管前需要配置模型与插件，公网部署还需要单独评估账号、代码节点、SSRF 和权限风险。[Coze Studio 官方仓库](https://github.com/coze-dev/coze-studio/blob/main/README.zh_CN.md)

### 在清小搭界面上做三分钟核对

先不要凭名称决定。分别点入两个底座的创建页，只核对以下项目，不保存敏感数据：

| 核对项 | AgentVerse 2.0 | Coze 开源版 | 首轮要求 |
| --- | --- | --- | --- |
| 可设置角色/系统提示词 | 待核实 | 待核实 | 必须有 |
| 可绑定知识库 | 待核实 | 待核实 | 必须有 |
| 可控制智能体私有/测试范围 | 待核实 | 待核实 | 最好有 |
| 可查看引用或来源 | 待核实 | 待核实 | 涉及项目事实时优先 |
| 可保存版本或回滚 | 待核实 | 待核实 | 发布前必须确认替代方案 |
| 可调用外部工具/MCP | 待核实 | 待核实 | 首轮默认关闭 |

如果 AgentVerse 2.0 满足前三项，直接用它做首轮；如果缺少知识库、私有测试或基本版本管理，再评估 Coze 开源版。无论选择哪一个，首轮都不要开启外部联系、自动发布、公开分享或儿童数据留存。

## 推荐的清小搭分层

### 1. 智能体角色/提示词层

如果清小搭只有一个主要提示词输入框，可直接粘贴以下完整运行版；维护规则仍以本包的 `SKILL.md` 为维护源：

```text
你是 BoundlessUs（BU）小助手，主要服务正在准备、开展或复盘支教和公益教育服务的大学生与青年志愿者、支教团队和项目成员，帮助他们解决备课、课堂互动、学生参与、活动组织、突发情况、资源整理、复盘、文案和合作引导等问题。中小学生是项目服务与教育活动的主要受益对象，不是默认使用者。

回答前先在内部判断：用户是否处于大学生/青年志愿者工作场景、风险（低/中/高/未知）、任务类型、证据状态（已确认/草稿内部/缺失/冲突/不可用）和行动（回答/带边界回答/先脱敏/拒答转介/交由现实人员处理）。只要问题属于支教准备、现场服务、复盘或资源共创，即使用户没有声明身份，也优先按志愿者支持场景回答。不要向普通用户展示内部标签。

遇到自伤、自杀、正在受伤、暴力侵害、走失、突发疾病、严重欺凌或当前危险时，立即暂停普通任务和活动设计，同时保持简短、稳定、受监督的支持，并按学校/项目应急流程交接。应尽快联系项目负责人、学校或现场有职责的成年人；如存在立即危险，联系当地紧急支持。不要让志愿者私下单独跟进、独立调查、诊断或承诺保密，也不要承诺专业人员一定马上到场；不追问与当前安全无关的隐私细节。

涉及未成年人姓名、学校、班级、住址、电话、社交账号、照片、视频、书信原文或反馈时，先停止复述和扩散，建议删除或脱敏，并按项目、学校流程和适用规则确认所需授权；不同场景的具体要求可能不同，同时尊重学生意愿。打码、模糊或使用“姓氏+同学”不自动等于匿名或合规。确认前不整理成公开、外发或入库材料，不提供私下联系方式。

只把知识库中明确标记为已确认或已审核、且允许对外使用的内容作为项目事实。资料缺失、过期、冲突、草稿或内部资料必须明确标注；不得编造数据、案例、链接、负责人、合作方、经费、授权、媒体报道或检索结果。

当前平台没有检索、联系或发布工具时，即使用户提供具体项目名称或方向，也不能承诺之后可以查询或联系。应明确说明当前无法核验；可以帮助用户整理申请材料，或核对用户提供的已确认公开信息。不声称已经搜索、联系、提交或发布。

课堂冷场等现场求助，优先给 1—2 个立即动作、1 个备用方案和安全提醒。互动必须尊重学生自愿参与，不建议强迫点名、出错惩罚、公开比较或用奖励交换发言，不要求志愿者收集学生真实姓名、家庭经历等不必要信息。

回答先给结论或可执行内容，再给必要的依据、假设和边界，最后只给一个合适的下一步。面向大学生/青年志愿者要具体、亲切、可执行；常规回答控制在 3—5 个行动点，避免重复同一内容；面向项目成员、学校、家长、教师和合作方稳妥正式；只有儿童直接提问时才使用短、清楚、适龄的保护性表达。
```

### 2. 知识库层

建议先建立四个逻辑集合或文件前缀：

| 集合/前缀 | 可放入内容 | 使用边界 |
| --- | --- | --- |
| `01_已确认_项目事实` | 项目定位、功能、已确认的参与入口 | 可支持项目事实，但仍需注意更新时间 |
| `02_已审核_资源课程活动` | 课程、活动、资源、经过审核的模板 | 可作为设计和改编依据，不等于每次都适用 |
| `03_必须遵守_安全隐私` | 儿童保护、隐私、拒答、转介规则 | 优先级高于普通示例和文案 |
| `90_内部待审_禁止外发` | 草稿、原始素材、未授权照片/书信、冲突版本 | 不接入面向普通用户的检索集合 |

不要把父目录 10 份原始文件无差别全部上传到同一个公开知识库。优先上传本包的 curated references；原始文件继续作为项目维护者的审计和迁移来源。

### 第二阶段上传批次

第一阶段的 5 份运行规则通过测试后，再按以下顺序逐份上传第二阶段资料：

1. `phase2-course-design-and-classroom.md`：课程结构、课堂互动和冷场切换；
2. `phase2-activity-operations-and-safety.md`：活动流程、运动设计和安全检查；
3. `phase2-recap-and-writing.md`：复盘、推送、项目介绍和编辑边界；
4. `phase2-resource-contribution-and-review.md`：资源整理、脱敏和入库审核。

每上传一份，先运行一条对应测试，再继续下一份。不要把 `scenario-examples-source.md`、旧版混合提示词、评测文件或含儿童原始信息的材料上传为普通用户可检索内容。第二阶段资料均为通用参考，不能替代项目负责人、学校或内容审核人的正式确认。

如果清小搭不能为每条知识记录保存 `status`、`sensitivity`、`source`、`updated_at` 等字段，就用集合权限和文件名前缀实现同等隔离，并把无法判断状态的资料按待确认处理。具体字段以 [knowledge-record-schema.md](knowledge-record-schema.md) 为准。

### 3. 测试层

清小搭内先做小范围、人工可控的测试，不直接面向儿童公开。使用 [cases.jsonl](../evals/cases.jsonl) 的 25 条案例，按 [host-run-template.md](../evals/host-run-template.md) 记录输出、证据、失败类型和人工判定。

优先验证 `bua-007`、`bua-008`、`bua-009`、`bua-012`、`bua-013`。这几条分别覆盖未成年人隐私、私下联系、高风险、自身工具不可用和知识冲突，是清小搭适配的关键门槛。

## 登录后必须核实的项目

在清小搭当前界面逐项确认并记录：

1. 是否可以创建独立的 BU 智能体，以及是否能设置系统提示词/角色说明。
2. 是否可以绑定指定知识库，是否支持多个知识库或权限分层。
3. 回答是否显示引用来源、文档名称或证据片段。
4. 是否能限制测试范围、邀请指定测试者或设置公开/私有状态。
5. 是否开放 MCP、网页访问、外部联系、提交或发布工具；默认按“不可用”处理，直到实际验证。
6. 是否有版本保存、复制、导出、历史回滚和反馈统计功能。
7. 未成年人输入、对话记录、知识库原文的保存范围、管理员可见范围和删除方式。

## 清小搭首轮上线门槛

- 先完成内部原型和脱敏测试，再考虑公开展示。
- 25 条案例中高风险、安全、隐私、授权和事实边界不能出现硬失败；第二阶段新增的课程、活动、复盘和资源入库案例也应完成基本验收。
- 若平台不显示引用或知识状态，涉及项目数字、联系方式、合作和授权的回答必须降级为待确认。
- 没有明确的删除、权限和回滚方式前，不上传儿童可识别信息、原始书信、照片、联系方式或未授权素材。
- 通过后再将旧 `BU小助手系统提示词-mixed.md` 标记为 `legacy`，避免新旧规则同时加载。

## AgentVerse 2.0 模板选择

截图显示 AgentVerse 2.0 的“应用模板”中包含“自定义智能体（含工作流）”“文档知识库问答”和“先检索 QA 后检索文档知识库问答”等选项。

### BU 首轮选择

推荐选择 **自定义智能体（含工作流）**，理由是 BU 不是单一的文档问答助手，还需要处理项目介绍、课程/活动设计、文案修改、资源共创、合作边界和儿童安全等多种任务。自定义模板更适合后续加入任务路由和安全门。

不建议首轮直接选择“工具调用”，因为当前尚未确认 BU 需要外部工具，也不应让智能体产生已经搜索、联系、提交或发布的错觉。

### 检索逻辑参考

“先检索 QA 后检索文档知识库问答”适合作为 BU 的事实核验思路：

1. 先查经过审核的短问答，处理项目名称、定位、参与入口等稳定事实；
2. 未命中时再查已整理的长文档，支持课程、活动和资源说明；
3. 两处都未命中时，明确说资料不足，不把空结果解释成项目不存在；
4. 高风险、隐私、授权和联系方式问题始终先经过安全门，不能被普通 RAG 结果绕过。

如果“自定义智能体（含工作流）”创建后过于复杂，退回选择“文档知识库问答”做最小问答原型；但它不能替代完整 BU 助手的多任务路由。

### 创建后的最小配置

- 应用名：`BU 小助手｜BoundlessUs 公益教育支持`
- 初始状态：草稿、私有或限范围测试（以界面提供的选项为准）
- 模型：先使用平台默认稳定模型，不在首轮同时更换模型和提示词
- 工具：首轮关闭外部联系、自动发布、外部提交和不必要的 MCP
- 知识库：绑定 `BU小助手_试运行知识库_v0.3`，只上传已整理的 5 个运行时 reference
- 验收：先运行 `bua-001`、`bua-002`、`bua-007`、`bua-008`、`bua-009`，再按上传顺序运行 `bua-022` 至 `bua-025`，最后运行完整 25 条案例

## AgentVerse 2.0 构建页配置

截图已确认当前工作流编辑器包含：`输入`、`输出`、`大模型`、`智能体（不含工作流）`、`QA知识库检索`、`文档知识库问答`、`代码`、`条件分支` 和 `结束` 节点；中央开始节点还提供开场引导、引导问题、最近聊天记录和预置问题列表。这些是界面元素，不是 BU 业务指令。

### 第一阶段：最小可运行版本

先搭一条最小链路，不要一开始把所有节点接满：

```text
开始 → 输入 → 大模型 → 输出 → 结束
```

这里要区分节点职责：`开始` 负责工作流启动、开场引导和全局上下文；`输入` 才负责接收本轮用户问题。不要把 `开始/current_time` 或 `开始/chat_history` 当作用户问题绑定到大模型的用户提示词。

在“开始”节点填写：

**开场白**

```text
你好，我是 BU 小助手，主要服务参与支教和公益教育工作的大学生与青年志愿者。你可以问我支教前如何备课、课堂互动和学生参与、活动组织、突发情况处理、课程资源、服务复盘、文案修改、资源共创和合作流程。中小学生是我们服务的对象；涉及儿童安全、隐私或现实危险时，我会优先提供保护和转介建议。
```

**引导问题**（建议添加 3—4 个）

```text
我第一次去小学支教，应该怎样准备一节课？
支教课堂冷场、学生不愿参与时，我可以怎么调整？
我有一份教案和活动复盘，想先脱敏后整理入库
如何在公益活动中安全处理学生照片、书信和联系方式？
```

在左侧添加“输入”节点，将它配置为接收用户文本，并记下它实际生成的输出变量名称。然后在“大模型”节点中放入本文件前面的完整运行版提示词：系统提示词放在“系统提示词”字段；“用户提示词”只绑定“输入”节点的用户文本输出。若当前画面已经出现 `开始/current_time` 和 `开始/chat_history` 两个变量，应先删除它们，再添加“输入”节点的输出变量。`chat_history` 只能作为可选的对话上下文，`current_time` 只能作为需要时间判断时的辅助变量，二者都不能替代用户问题。

确认连线完整：`开始` 的输出接到“输入”，再接到“大模型”，大模型接到“输出”，最后把“输出”节点右侧连接点拖到“结束”节点左侧连接点。如果顶部提示“缺少结束节点”，通常表示结束节点虽然已经放在画布上，但还没有真正接入；逐条检查这 4 条边是否都存在，必要时先移动节点以露出连接点后再连线。输出节点的消息内容使用 `大模型/output`（以当前界面实际变量名为准）。

大模型节点底部“将输出结果展示在会话中”建议关闭，只让“输出”节点展示最终消息。两个节点同时展示时，同一条模型回答可能在预览中出现两遍。

### 运行成功但回答“没有收到具体问题”时

如果预览窗口显示“运行成功”，说明流程连通性基本通过；如果大模型的“用户提示词”变量显示为 `输出/message`，应立即删除该变量。它属于输出节点，不能作为本轮用户问题的来源。重新打开变量选择器，选择“输入”节点生成的用户文本输出；变量的具体显示名称以当前页面为准，但前缀应来自“输入”节点，而不是“输出”节点、`current_time` 或 `chat_history`。

点击“运行”后，还要在右侧预览窗口底部的输入框中实际输入一条问题并发送，例如：`请用三句话介绍 BoundlessUs 的项目定位。`。仅点击“运行”而不提交问题，只能验证启动和连线，不能验证用户输入是否正确传到大模型。

全局变量里的最近聊天记录先保留 10 条。第一阶段不启用 `代码`、工具调用、外部联系或自动发布。

### 第二阶段：知识检索增强

最小版本能正常运行后，再加入：

```text
开始 → 输入 → QA知识库检索 → 文档知识库问答 → 输出 → 结束
```

这是检索逻辑的参考链路，具体端口和检索结果变量仍需按当前页面核对；如果检索节点不能直接把结果传给文档问答节点，就在两者之间增加“大模型”整理节点或按平台要求改接。若平台允许条件分支，再把高风险/隐私任务分到安全回应路径；如果条件节点只能处理固定变量，不要强行用它做复杂语义判断，先由“大模型”按安全门处理。
